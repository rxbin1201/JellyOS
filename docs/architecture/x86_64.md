# JellyOS x86_64 Architecture Layer

**Code:** [`kernel/arch/x86_64/`](../../kernel/arch/x86_64/), with the interface to generic code in [`kernel/core/arch.h`](../../kernel/core/arch.h)

Generic kernel code talks to the architecture only through `core/arch.h`
(README section 11). Everything below is private to `kernel/arch/x86_64/`.

## Initialization order (README section 12)

| Step | File | Notes |
|---|---|---|
| Early console | `early_console.c` | COM1, 115200 8N1. Runs first so every later step can log |
| CPU state | `cpu.c` | Feature detection (APIC, x2APIC, NX, TSC, 1 GiB pages), sets `CR0.WP` |
| GDT and TSS | `gdt.c` | Layout below. Loads CS, SS, DS and ES, then the TSS |
| IDT | `idt.c`, `isr.S` | 256 interrupt gates, one entry stub per vector |
| Exception handlers | `exceptions.c` | `#PF` goes to the VMM, `#DF` detects stack overflows, `#BP` logs and continues, everything else panics |
| Legacy PIC | `pic.c` | Remapped to 0x20–0x2F, all lines masked |
| *Memory* | `kernel/memory/` | PMM, kernel page tables (`paging.c`, PAT), heap. See memory.md |
| Reference timer | `pit.c` | PIT channel 2, used only to calibrate other timers |
| Local APIC | `lapic.c` | x2APIC (MSRs) if available, otherwise xAPIC (MMIO through `vmm_map_mmio`, uncached) |
| Periodic timer | `lapic.c` | Local APIC timer at 1000 Hz, drives `time/clock.c` |

`arch_init_cpu()` covers the steps up to the PIC. `arch_init_timer()` covers
the steps after memory initialization, because the xAPIC registers need an MMIO
mapping. Both run with interrupts disabled. `kernel_main` then switches to a
guarded stack (`arch_switch_stack`) and enables interrupts. Only the boot CPU
is used; SMP comes later.

## GDT

| Selector | Segment |
|---|---|
| `0x00` | Null |
| `0x08` | Kernel code (64-bit, DPL 0) |
| `0x10` | Kernel data |
| `0x18` | User data (DPL 3) |
| `0x20` | User code (64-bit, DPL 3) |
| `0x28` | TSS (16-byte descriptor) |

User data comes directly before user code because `SYSRET` derives both
selectors from one base (Phase 4).

### TSS and interrupt stacks

| IST | Used by | Size |
|---|---|---|
| 1 | `#DF` double fault | 16 KiB |
| 2 | NMI | 16 KiB |
| 3 | `#MC` machine check | 16 KiB |

These faults can occur on a broken stack, so they always switch to a known-good
one. `RSP0` (the ring 3 → ring 0 stack) is set to the current thread's kernel
stack on every context switch.

## User mode and system calls

| Item | Setting |
|---|---|
| `CR0` | `WP`, `MP` set; `EM`, `TS` clear |
| `CR4` | `OSFXSR`, `OSXMMEXCPT`; `SMEP`, `SMAP`, `UMIP` when supported |
| `EFER.SCE` | Set, `SYSCALL` enabled |
| `STAR` | Kernel `CS 0x08` / `SS 0x10`; SYSRET base `0x10` (user `SS 0x1B`, `CS 0x23`) |
| `LSTAR` | `syscall_entry` (`isr.S`) |
| `SFMASK` | Clears `TF`, `IF`, `DF`, `AC` on entry |
| `GS_BASE` / `KERNEL_GS_BASE` | Per-CPU block in the kernel / 0 in user mode, exchanged with `SWAPGS` |
| User `RFLAGS` | `0x202` (`IF`; `IOPL 0`) |

`syscall_entry` switches to the kernel stack from the per-CPU block and builds
the same `arch_interrupt_frame` as an interrupt from ring 3. It returns through
the common `interrupt_return` path with `IRETQ`. `SYSRET` is not used: it is
only a speed optimization and has well-known pitfalls with non-canonical
return addresses.

Interrupt stubs execute `SWAPGS` when the interrupted context was ring 3, and
`interrupt_return` does the same when going back to ring 3. Before every return
to ring 3, `thread_return_to_user()` handles pending kills and preemption.

New threads start in `switch.S`: kernel threads through
`arch_kernel_thread_start`, user threads through `arch_user_thread_start`,
which consumes a prepared interrupt frame and enters ring 3 with `IRETQ`.

Exceptions in ring 3 call `process_fault()` and end only that process. In
ring 0 they panic.

## Interrupt vectors

| Vectors | Use |
|---|---|
| `0x00`–`0x1F` | CPU exceptions |
| `0x20`–`0x2F` | Legacy PIC (masked). `0x27` and `0x2F` are spurious and ignored |
| `0x30`–`0xEF` | Device interrupts (IOAPIC, MSI/MSI-X; Phase 5) |
| `0xF0` | Local APIC timer |
| `0xFE` | Local APIC error |
| `0xFF` | Local APIC spurious |

Every stub builds a `struct arch_interrupt_frame` (general-purpose registers,
vector, error code, CPU frame) and calls `interrupt_dispatch()`. That function
calls the handler registered with `interrupt_set_handler()`. Exceptions without
a handler panic.

## Page tables

`paging.c` implements the generic primitives from `memory/mmu.h` on 4-level
tables:

| Generic flag | PTE bits |
|---|---|
| `VM_WRITE` | RW |
| `VM_USER` | US (intermediate entries get US in the user half only) |
| `VM_GLOBAL` | G (kernel mappings; `CR4.PGE` is enabled after the switch) |
| not `VM_EXEC` | NX (when supported) |
| `VM_WRITE_COMBINING` | PWT → PAT index 1 = WC |
| `VM_UNCACHED` | PCD + PWT → PAT index 3 = UC |
| `VM_OWNED` | Software bit 9 |

The PAT MSR is programmed as WB, WC, UC-, UC (repeated). Without PAT support,
write-combining falls back to uncached.

## Panic output (README section 45)

```text
*** KERNEL PANIC on CPU 0 ***
reason: page fault at 0x0000000000001000 (page not present, read, kernel)
RIP: 0xffffffff80001a13  arch_crash_test+0x43
CS / RFLAGS / RSP / SS, all general-purpose registers
CR0 / CR2 / CR3 / CR4
stack trace:
  0xffffffff80001a13  arch_crash_test+0x43
  0xffffffff800020e0  kernel_main+0x2b0
  0xffffffff8000000d  _start+0xd
*** system halted ***
```

The stack trace follows the RBP chain (the kernel is built with frame
pointers). Symbol names come from a table that is linked into the kernel in two
passes (`tools/debugger/ksyms.py`). The build fails if the second link moves any
function.

## Testing

See [../development/testing.md](../development/testing.md) for `make test`
and the `crashtest=` fault tests.

`make run KVM=1` and `make test KVM=1` run on the host CPU via KVM. That
exercises the x2APIC path, which QEMU's TCG emulation does not offer.
